Ward-Beck Audio Tap
Manual Windows macOS Linux

Linux setup

x86_64 PCs and ARM64 (Raspberry Pi 4 and 5) in one download. Needs PipeWire with pipewire-pulse, or PulseAudio. About one minute. version 2.2.1 · full

Install

  1. Download and unpack

    cd ~/Downloads
curl -LO https://github.com/WardBeckSystems/Ward-Beck-Audio-Tap/releases/latest/download/ward-beck-audio-tap-linux.tar.gz
tar xzf ward-beck-audio-tap-linux.tar.gz
cd ward-beck-audio-tap-linux

  2. Run the installer

    bash install.sh

    It picks the binary for your CPU, installs it to ~/.local/bin, and sets up a systemd user service that starts at login. It asks for your sudo password once, to let the Tap listen for PTP (ports 319/320 and raw Ethernet). Skip it and everything else still works; the Timing tab shows the command to run later.

  3. Open the web app

    Go to ward-beck.ca or xtm.wbsps.ca. Play something (YouTube, a player, a DAW): the meters move.

What you will see

WhereExpect
Sound settingsNew Ward-Beck virtual outputs (the wbs_… buses). Your normal speakers keep working; the Tap mirrors to them with a feedback guard.
Web appEverything: meters of the computer's sound, patchbay, generators, AES67 / SAP, Dante discovery, PTP / gPTP, NTP.
System monitorward-beck-audio-tab, about 0.7% CPU while metering.
After a restartStarts at login with your user session.

Update

Unpack the new download and run its bash install.sh. It stops the service, replaces the program, grants the PTP permission again (a new binary loses it) and restarts.

Remove

bash uninstall.sh

Other ways to run it

From a git checkout, bash linux/install.sh builds from source (needs Rust from rustup.rs). A container image is described in docs/DEPLOYMENT.md.

If something is wrong

You seeDo this
⚠ pactl not foundInstall pipewire-pulse (or pulseaudio-utils) and run install.sh again.
Meters do not moveChoose a Ward-Beck output in the app's or system's sound settings, or route it in the web app's patchbay.
Timing tab asks for a commandPTP permission was skipped. Run the command it shows once (it uses sudo setcap).
Service will not startjournalctl --user -u ward-beck-audio-tab -n 50 and send the output.

For any report, send the file from 127.0.0.1:8467/api/diagnostics/bundle (see If something is wrong).
