Audio Tap manual

The Tap is a small program that runs on your computer and gives the Ward-Beck web meters (ward-beck.ca, xtm.wbsps.ca) real audio, real network streams and real clocks to look at. version 2.2.1

How it fits together

Choose your computer

Windows 10 / 11

64-bit PC. Unzip, right-click install.ps1, Run with PowerShell. About 2 minutes. preview

macOS 14.2 or newer

Apple silicon or Intel. Unzip, run bash install.sh in Terminal. About 2 minutes. preview

Linux

x86_64 or ARM64 (Raspberry Pi 4/5), PipeWire or PulseAudio. bash install.sh. full

What to expect on each system

Linux is the reference system and has everything. Windows and macOS are previews in 2.2.1: the Tap installs, starts at login, answers the web app and handles network audio and clocks, but it does not yet capture the computer's own sound. That comes in a later release, without any extra driver to install.

Normal on Windows and macOS: the log lists Linux tools it could not find, for example ERROR [cmd] 'pactl' is not installed and the same for avahi-browse, timedatectl, chronyc, ip, aplay, amixer, wpctl and pw-dump. Each line means "that Linux feature is off here". It is not a fault.

On the NTP card the suggested fix commands are the Linux ones; on Windows and macOS set the time server in the system's own Date & Time settings instead.

Check that it is running

On any system, open http://127.0.0.1:8467/api/diagnostics in a browser on the same computer. You should see a page of text that starts like this:

{"tap": {"version": "2.2.1", "os": "windows", "arch": "x86_64", ... "port": 8467,
 "audio_backend": "WASAPI loopback (driverless)", ...

os is linux, windows or macos. If the page does not open, the Tap is not running: see the "If something is wrong" section of your system's page.

If something is wrong

  1. Get the diagnostic bundle

    Open http://127.0.0.1:8467/api/diagnostics/bundle and save the file. It holds the version, the system, what the Tap could and could not do, and the end of the log.

  2. Or send the log file

    If the Tap will not start there is no bundle; send the log instead.

    SystemLog file
    Windows%LOCALAPPDATA%\Ward-Beck\Audio Tap\logs\tap.log
    macOS~/Library/Logs/Ward-Beck Audio Tap/tap.log
    Linux~/.local/state/ward-beck-audio-tap/tap.log

  3. Say what you did and what you saw

    Which page, which button, what you expected, what happened. Open an issue at github.com/WardBeckSystems/Ward-Beck-Audio-Tap/issues and attach the file.
